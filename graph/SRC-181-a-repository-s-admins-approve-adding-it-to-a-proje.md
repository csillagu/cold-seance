# SRC-181: A repository's admins approve adding it to a project

A repository ([SRC-180](SRC-180-repositories-are-their-own-item-in-the-tool-with-a.md)) is added to a project only when one of the repository's admins approves it.

As received: "Repositorys have admins, those can approve adding them to projects."

The stakeholder had said earlier in the same session: "Manual approval is definitely out of picture." The drafting agent read this as ruling out a central gatekeeper, not the repository admins' own approval, and said so; the stakeholder did not object, but did not confirm the reading either.

The drafting agent reads "adding to a project" as covering both seeding a project from the repository ([SRC-074](SRC-074-a-project-can-be-seeded-from-existing-github-repos.md)) and pulling its new issues ([SRC-169](SRC-169-a-project-sets-which-repositories-it-pulls-issues.md)), since the stakeholder's concern was onboarding a repository and seeding onboards one too. The stakeholder has not confirmed this reading.

Not stated: whether someone who is admin of both the repository and the project still needs a separate approval; whether a repository admin can reject a request or withdraw an approval later, and what then happens to the project's tasks from that repository; how a repository admin learns of a request; whether one admin's approval is enough when a repository has several.
