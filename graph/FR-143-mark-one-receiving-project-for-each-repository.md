# FR-143: Mark one receiving project for each repository

The system must let the admin of a project that pulls issues from a repository mark that project as the repository's receiving project, the one that gets its new issues ([SRC-177](SRC-177-one-receiving-project-per-repository-gets-its-new.md), [SRC-178](SRC-178-the-receiving-project-is-marked-by-a-project-admin.md)). It is done when, after the marking, the repository's receiving project is that project.

It serves [UC-009](UC-009-triage-a-task-that-arrived-from-github.md) and [UC-025](UC-025-manage-a-project-s-members.md).

Origin: composed by Claude from the items linked above, for issue #5. For issue #11, after its quality reviews, what happens when the receiving project stops pulling was left to FR-157, refusing a second receiving project went to FR-179, and the item was worded as what the system does. The wording is Claude's, not the stakeholder's; every obligation rests on a linked item.
