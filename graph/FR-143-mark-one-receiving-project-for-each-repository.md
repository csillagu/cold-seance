# FR-143: Mark one receiving project for each repository

The system must let the admin of one of the projects that pull issues from a repository mark that project as the one that receives the repository's new issues ([SRC-177](SRC-177-one-receiving-project-per-repository-gets-its-new.md), [SRC-178](SRC-178-the-receiving-project-is-marked-by-a-project-admin.md)).

When the receiving project stops pulling issues from the repository, it stops receiving the repository's new issues ([SRC-190](SRC-190-a-withdrawn-approval-stops-the-project-pulling-its.md)). No project then receives them ([SRC-215](SRC-215-after-the-receiving-project-stops-pulling-no-p.md)).

It serves [UC-009](UC-009-triage-a-task-that-arrived-from-github.md) and [UC-025](UC-025-manage-a-project-s-members.md).

Origin: composed by Claude from the items linked above, for issue #5. That no project then receives them was added for issue #11 from SRC-215. The wording is Claude's, not the stakeholder's; every obligation rests on a linked item.
