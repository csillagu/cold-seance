# SRC-293: An API token is given a name when it is created

A personal API token is given a name, which is required, when it is created, and the name is shown wherever the person's tokens are listed.

As received, in the design session of 2026-11-23, recorded in issue #256 (the UI/UX review of the demo deployment). Asked, about items 42 and 48 ("API tokens have no name", "Proposals are named only by their timestamp"), "What should name them?", with the options "Token name required, proposal title optional" ("A token gets a required name when created. A proposal may carry a title given through the REST API/MCP; without one it is named by its creator and projects."), "Both optional" and "Derived only", the owner chose "Token name required, proposal title optional".

Not stated: whether two of a person's tokens may have the same name.
